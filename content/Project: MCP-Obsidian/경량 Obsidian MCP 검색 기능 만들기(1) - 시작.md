# 1. 배경
- 나는 mcp-obsidian(npm 15K+)이라는 오픈소스 MCP 서버를 사용하고 있다.
- 그런데 검색 기능이 단순히 `indexOf` 문자열 검색으로 수행되기에 너무 빈약하다.
	- 특히 다음 두 가지 케이스를 커버할 수 없어 아쉽다.
		1. "검색 키워드를 노트가 포함한다"고 해서 보여주는 게 아니라, 그 중 가장 큰 관련성을 갖는 노트를 보여줘야 한다. (AI가 수십개의 노트를 하나하나 뒤져보다 토큰 사용량이 엄청 나오는 경우가 흔하다....)
		2. 옵시디언 노트들의 특성상, 오타 혹은 의미는 같지만 다른 표현("스프링부트" → "Spring", "스프링", "스프링 부트", "스프리ㅇ")들이 자주 나오기에, 이를 적절히 고려할 수 있어야 한다.
- 물론 chatgpt나 ollama embedding을 집어 넣어 의미를 이해하는 검색 기능이 들어가면 좋겠지만... 너무 무겁고 외부 API 호출이 필요하다. (Obsidian SmartConnection 돌릴 때 엄청난 렉이 걸린 것만 생각해봐도 사용자들이 원치 않아 할 것 같다...)
- 특히, 해당 오픈소스가 lightweight + zero dependency를 지향하기에 오픈소스의 성격과 적절치 않다. (Obsidian의 설계 이념과 맞닿아 있다)
- 때문에 충분히 가벼우면서도 기존보다 더 나은 검색 기능을 제공할 방법이 필요하다.
