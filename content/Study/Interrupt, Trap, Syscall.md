# 1. 분류 체계
```text
Interrupt
├── Hardware Interrupt (타이머, 키보드 등 물리적 장치)
└── Software Interrupt (Exception)
    ├── Trap (자발적: syscall 명령어, breakpoint 등)
    └── Fault (비자발적: divide-by-zero, page fault 등)
```

- **Interrupt**는 `int` Op나 전기적 신호(타이머, 키보드)를 통해 CPU를 커널 모드로 만들고 IVT에서 인터럽트 번호를 오프셋으로 하여 적절한 인터럽트 핸들러를 실행하는 메커니즘을 뜻함.
- **Exception**은 소프트웨어적으로 발생하는 모든 인터럽트(User Mode → Kernel Mode)를 뜻함.
	- **Trap**은 Exception 중에서도, 프로그램이 자발적으로 발생시키는 경우(syscall, breakpoint)를 뜻함.
	- **Fault**는 의도치 않은 Exception(e.g., Divide by zero(`0x00`), Page fault(`0x0E`))를 뜻한다.
- **Syscall**은 `0x80` 인터럽트를 통해 수행하는 OS의 여러 서비스와 그를 위한 인터페이스 자체를 뜻함.

# 2. Trap의 동작 원리
- 소프트웨어 인터럽트로도 불린다.
- "지금 커널 모드로 전환해라"라고 명령하는 CPU 명령어다. `syscall`이나 `int 0x80` 같은 어셈블리 명령어가 바로 trap이다.
- 여기서 `0x80`은 인터럽트 번호로, 다양한 인터럽트 중에서도 소프트웨어 인터럽트(trap)를 지칭하는 번호다.
	- `int 0x80`에서 `0x80`은 시스템 콜 번호를 의미하는 게 아니다. 하드웨어 인터럽트에는 다양한 종류가 있고, 그 중에서 시스템 콜을 일으키는 소프트웨어 인터럽트(trap)가 `0x80` 이라는 인터럽트 번호를 갖는 것이다.

#### ◼️ 실행 흐름
- 부팅 시에 OS는 메모리의 어딘가에 인터럽트 벡터 테이블(IVT)를 세팅한다. 이 배열은 시스템 콜 번호를 각 인터럽트의 핸들러(Interrupt Service Routine)가 위치한 주소(포인터)를 저장하고 있다.
- 실제 실행 흐름:
	1. `%eax` 레지스터에 시스템 콜 번호(`0x80`)를 저장한다.
	2. `%ebx`, `%ecx`, `%edx` 등 레지스터에 시스템 콜 인자를 저장한다.
	3. `int 0x80`을 실행하여 소프트웨어 인터럽트를 일으킨다.
	4. cpu는 커널 모드로 전환되고, `%eax`에 저장된 시스템 콜 번호를 오프셋으로 하여 IVT에 저장된 ISR에 접근한다.
	5. 찾은 핸들러가 실행되며 인터럽트를 처리한다.

# 3. 현대의 Syscall
- 과거에는 `int 0x80`이 일어난 경우, IVT 벡터에 운영체제가 등록해 둔 핸들러는 레지스터에 정확한 syscall 인자가 들어있을 것을 기대하여 분기 처리했다. (e.g., eax 레지스터 값 확인 후 시스템 콜 테이블을 참조하여 실제 커널 내부 함수에 실행 흐름을 넘김)
- 그러나 이 방식은 syscall 핸들러가 정확한 시스템 콜 내용을 확인하기 위해 각종 하드웨어 상태 레지스터를 뒤져 분기처리해야 했다. → 불필요한 연산 오버헤드
- 최근에는 Trap 종류에 따라 다른 인터럽트 번호를 할당하여 분기 처리의 오버헤드를 제거한다. → Trap 처리에 필요한 단서들을 하드웨어 레벨에서 미리 준비할 수 있어 빠르다. (e.g., 페이지 폴트 인터럽트(`0x0E`) 발생 시 `CR2` 레지스터 조회)
- → 이 덕분에 Trap의 종류에 따라 하드웨어 레벨에서의 인터럽트 우선순위 설정이 더 쉽다는 장점도 존재한다.
